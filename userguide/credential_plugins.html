10. Secret Management System

Credential plugins let a credential field obtain its value from an external secret management system. Create a source credential to authenticate to that system, then link a field of a target credential to the source and supply lookup metadata. The source stores connection/authentication settings; metadata belongs to each individual field link and identifies what to retrieve.

Koios Automation Platform 2026.11.8 loads the following 10 external credential types. Secret fields in the source credential are encrypted in the database. A lookup does not remove the need to protect the account used to access the external system. See Credential Types for plugin availability, the opt-out setting and custom-type collisions.

10.1. Configure and link a secret lookup

  1. Open Automation Execution > Infrastructure > Credentials and click Create credential. Give the source a Name, select one of the external Credential type values below, enter its connection/authentication fields, and click Create credential.

  2. Open or create the target credential, for example a Machine credential. For an existing target, click Edit credential. An external credential cannot itself use another external lookup for its fields.

  1. Click the key icon beside the target input. Its tooltip is Populate field from an external secret management system. For a saved encrypted text field the key button is disabled until the field is made editable; it is also disabled while Prompt on launch is selected.

  2. In the Credential Plugins dialog, under Select external credential, choose the source in Credential. Complete the Metadata fields for that particular lookup.

  3. Optionally click Test. Test passed. verifies the lookup, not the target account’s ability to connect to another service. The dialog stays open with the values you entered.

  4. Click Finish to attach the lookup to the target field. Repeat for other fields as needed, then click Create credential or Save credential on the target form to persist the links. Test alone does not save them. The linked field displays a managed-value placeholder and explanatory helper text rather than the retrieved secret.

The controller retrieves linked values when preparing automation that uses the target credential. A failure to retrieve a required value can prevent that automation from running. Test network reachability, certificates, source permissions and metadata before relying on a lookup.

In the tables below, Credential fields are entered when creating the source credential; Link metadata is entered in the key dialog on the target. Required reflects the deployed schema. External-system policy can require additional values.

10.7. GitHub App Installation Access Token Lookup

Create and install a GitHub App with the permissions needed by the destination use case. Supply its app/client ID, installation ID and PEM RSA private key. The plugin retrieves an installation access token. Its sole metadata field is Description (Optional); it does not select the installation or permissions. For repository checkout, link the returned token to the Password field of a Source Control credential and provide the appropriate GitHub App username for that checkout.

10.8. HashiCorp Vault Secret Lookup

Choose the authentication values appropriate to the Vault configuration, such as Token, AppRole credentials, a client certificate/key, or Username and Password. A listed authentication field is not a guarantee that the server permits that method. Set API Version to v1 or v2 to match the KV engine. The source credential’s Path to Auth is the default authentication mount; the linked field’s Path to Auth can override it. For KV v2, use Secret Version (v2 only) to select a version or leave it empty for the latest. The namespace option applies to Vault Enterprise.

10.9. HashiCorp Vault Signed SSH

This lookup returns a signed SSH certificate, not the private SSH key. Link it to Signed SSH Certificate on a Machine credential, keep the corresponding SSH Private Key on that Machine credential, and provide its unsigned public key in Unsigned Public Key. Select the signing mount in Path to Secret and the signing role in Role Name. The target SSH server must trust the signing authority and permit the certificate’s principals. Authentication fields and the two Path to Auth settings work as described for HashiCorp Vault Secret Lookup.

10.12. OIDC workload identity

The HashiCorp Vault OIDC lookup variants are not available in this release because FEATURE_OIDC_WORKLOAD_IDENTITY_ENABLED is disabled. They are not among the 10 types above. Use the non-OIDC Vault types with an authentication method configured on the Vault server; do not select an OIDC type or expect an automatically generated workload identity token.

Developers can consult the development docs for credential plugins for the plugin interface.

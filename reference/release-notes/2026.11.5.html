Koios Automation Platform 2026.11.5 — release notes

Published 2026-11-03 and reissued 2026-11-06 in the private registry ghcr.io/koiosplatform. Catalog: ghcr.io/koiosplatform/koios-operator-catalog@sha256:6a003e5a03d412f16d3edfe9d369c0a71e6f20446db4d9b63fdcee9e5555c4b7 (see olm-install.md).

Security maintenance release: all 14 images are rebuilt from the same upstream code as 2026.11.4, with current system packages and security updates. No KoiosPlatform changes are needed.

Reissue of 2026-11-06

The first 2026.11.5 (catalog 1150f739…) is withdrawn. If you installed it, point the koios-operators CatalogSource at the new catalog digest. OLM does not reinstall a CSV with the same version on its own: delete the 2026.11.5 CSV (koios-operator.v2026.11.5-cluster-scoped or, in the stable-2026.11 channel, koios-operator.v2026.11.5) and, if the Subscription stays in UpgradePending, recreate it with the same spec. Without OLM, fetch the moved 2026.11.5 tag of koios-installer (git fetch --tags --force) and apply kustomize/operators from it again.

Upgrading from 2026.11.x

Point the koios-operators CatalogSource at the new catalog digest. OLM upgrades the operators in the stable-2026.11 and stable-2026.11-cluster-scoped channels (koios-operator.v2026.11.5 replaces v2026.11.4), and the platform rolls out the new images. Without OLM, apply kustomize/operators from the 2026.11.5 tag of koios-installer.

Security

  • No CRITICAL vulnerabilities, as in 2026.11.4. Findings with an available fix go down from 52 to 47; the remaining ones need upstream changes (version limits in django-ansible-base, pulpcore and other dependencies, the Java libraries of the decision environment, and Twisted, which only has release candidates).

  • setuptools 80.10.2 in the controller and the platform gateway (fixes its bundled wheel and jaraco.context).

  • Current system packages in every image (for example Java 17 in the decision environment and curl), on the latest UBI 9.8 base; the UI is built with Node.js 24.22.2.

Fixes

  • Restoring a backup next to the original platform: while the restore ran, the new platform’s gateway could send requests to the services of the original platform until its own services were up. The restored gateway now starts without the service nodes copied from the original, so it sends no requests to the original services; each service is registered as it comes up. Fixed in the reissue of 2026-11-06, which only changes the gateway operator.

  • The postgres_image_version description of KoiosPlatformBackup and KoiosPlatformRestore is now in English.

  • The EDA and automation hub operators no longer create an empty redhat-operators-pull-secret Secret in the platform namespace. When operators and platform share a namespace, that placeholder could replace the registry pull Secret, and operator pods restarted later failed to pull their images.

Validated

  • Kubernetes (k3d): platform reconciliation with the new operands and operators, jobs through the gateway, a rulebook activation that launches a controller job with the new decision environment, and organization and team synchronization to controller, EDA and automation hub.

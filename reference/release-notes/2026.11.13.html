Koios Automation Platform 2026.11.13 — release notes

Published 2026-11-18 in the private registry ghcr.io/koiosplatform. Catalog: ghcr.io/koiosplatform/koios-operator-catalog@sha256:a5c46a396992908704cbf254667909cc0b35ec6517f22b15fa3dc836a5d96869 (see olm-install.md).

Koios configuration-as-code collections. No KoiosPlatform changes.

Upgrading from 2026.11.x

Point the koios-operators CatalogSource at the new catalog digest. OLM upgrades the operators in the stable-2026.11 and stable-2026.11-cluster-scoped channels (the 2026.11.13 bundles replace the 2026.11.12 ones), and the platform rolls out the new images. Without OLM, apply kustomize/operators from the 2026.11.13 tag of koios-installer.

Changes

  • Koios collections. Six configuration-as-code collections in the koios namespace, built from the upstream sources of the collections used with AWX and the reference platform, with the platform release as their version: koios.controller, koios.platform (platform gateway), koios.eda, koios.hub, koios.configuration (roles that apply a whole configuration) and koios.configuration_extended (configuration from a directory tree and deletion of what was removed from it). Modules, roles and variables are the same as in the current upstream collections; moving a repository is a matter of changing the prefix of the fully qualified names. They are community builds, not supported by Red Hat.

  • Where to get them. They are installed in the Koios execution environment (tarballs in /opt/koios-collections/casc), casc/hub-collections.yml of koios-installer publishes them to the platform automation hub, and they are published in the koios namespace of Ansible Galaxy (ansible-galaxy collection install koios.configuration_extended installs the six).

  • koios.configuration has no controller_applications role, so its dispatch role can follow object_diff.

  • Controller collections. koios.controller and ansible.controller reach automation controller through the platform gateway without extra settings, also in the export and import modules.

  • The execution environment keeps awx.awx, ansible.controller and ansible.platform for existing repositories.

Images

The controller, Event-Driven Ansible, automation hub, UI, platform gateway and execution environment images are rebuilt; the four operators carry their digests. Every other image is the 2026.11.12 one.

Validated

  • OpenShift (single-node, 4.21): upgrade from 2026.11.12 through the stable-2026.11-cluster-scoped OLM channel, operator Succeeded, platform Successful, the platform gateway and automation controller versions, a job with the new execution environment and configuration as code with koios.controller.

  • Kubernetes (k3d): configuration of the platform gateway, automation controller, Event-Driven Ansible and automation hub using only the Koios collections (dispatch, and per-environment configuration with filetree_read and object_diff), koios.controller alone, the upstream collections of the execution environment, the hub publishing playbook with the nine collections, and the manifests of the installer.

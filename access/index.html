Authentication and access

Users sign in to Koios Automation Platform once, at the platform gateway. The gateway authenticates them, keeps their session, and passes their identity to automation controller, Event-Driven Ansible and automation hub. Users, organizations and teams are managed in the gateway and shared by every service, so there is a single place to configure how people log in and what they are given when they do.

  • Authentication methods: the sources users log in with (the local database, LDAP, SAML, OIDC and other providers), their order, and how to add one.

  • Authentication providers: the settings of each type, and what to set up on the provider side.

  • Mapping: rules that grant access, organization and team membership, roles and the superuser flag from what the provider says about the user.

  • Sessions and passwords: session length, simultaneous sessions, password rules, the login page and the other gateway security settings.

  • API tokens and OAuth applications: tokens for scripts and integrations, and applications for external services.

All of this is in the user interface under Access Management and Settings > Platform gateway, and in the gateway API under /api/gateway/v1/. Only platform administrators (superusers) can change authentication; platform auditors can view it.
